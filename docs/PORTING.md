# Перенос веб-версии в настольную программу

Что именно изменилось по сравнению с [веб-версией](https://github.com/KennyS44/Journeyman),
почему так и что осталось сделать.

## Что решает задачу

Требование звучало как «программа для ПК без использования браузера». Оно
раскладывается на два разных требования, и выбрано первое:

1. **Пользователь не открывает браузер.** Есть окно, ярлык, установщик.
   Движок браузера внутри есть, но он вшит в программу и невидим.
2. Движка браузера нет вообще — это переписывание интерфейса на нативном
   тулките: холст, редактор форматированного текста с таблицами, галерея,
   плеер. От нынешнего проекта уцелел бы только парсер выражений.

Выбран Electron: весь интерфейс переносится дословно, а работы остаётся ровно
столько, сколько нужно на замену хранилища. Цена — вес: установщик около
90–100 МБ вместо мегабайта веб-версии, потому что Chromium едет вместе с
программой. Tauri дал бы 10–15 МБ за счёт системного webview, но потребовал бы
Rust в сборке и разного поведения движков на разных системах.

## Что перенесено дословно

Без единой правки: `ui.js`, `calc.js`, `app.js`, `screens/menu.js`,
`screens/space.js`, `screens/node.js`, `css/app.css`. Это примерно 2900 строк —
весь интерфейс и вся логика экранов.

Так вышло не случайно. В веб-версии действовало правило: экраны знают только
`DB`, `UI` и `APP`, а `DB` не знает про DOM. Замена одного слоя целиком стала
возможной именно поэтому.

## Что заменено

### Хранилище: IndexedDB → файлы

| было (web) | стало (desktop) |
|---|---|
| IndexedDB, 4 хранилища | `db.json` — записи, `assets/<id>.bin` — файлы |
| `Blob` прямо в базе | обычный файл на диске, метаданные в JSON |
| транзакции браузера | запись всего JSON атомарно: временный файл + переименование |
| квота браузера | место на диске |
| чистка данных сайта уносит всё | папку видно, её можно скопировать и унести |

Интерфейс модуля сохранён полностью: `listSpaces`, `createNode`, `addAsset` и
остальные шестнадцать методов принимают те же аргументы и возвращают ту же
форму данных. Поэтому экраны не заметили подмены.

Две тонкости, которые пришлось решить в адаптере `src/renderer/js/db.js`:

- **`File` не проходит через мост.** Renderer читает содержимое в `Uint8Array`
  и отдаёт байтами; обратно приходит то же самое, и `Blob` для показа
  собирается на месте — второго чтения с диска не требуется.
- **Экраны ждут готовые `Blob`.** `listAssets` подтягивает содержимое всех
  файлов объекта — как это делала и версия на IndexedDB. Для объекта с сотней
  мегабайт музыки это заметная память; правильное решение — отдавать файлы по
  собственному протоколу `jm-asset://<id>` и не грузить их целиком. Пока не
  сделано осознанно: сначала работающий перенос, потом оптимизация.

### Прочие замены

- **Шрифты** больше не грузятся с Google Fonts: 18 файлов `woff2` лежат в
  `src/renderer/fonts` (только кириллица и латиница), лицензии рядом. Без
  этого программа без интернета показывала бы запасной шрифт.
- **CSP** запрещает загрузку чего-либо извне. Для программы, которая обязана
  работать офлайн, это заодно страховка: вставленный в текст HTML не сможет
  ничего подтянуть из сети.
- **Окно** помнит размеры и разворот, программа запускается в одном экземпляре,
  внешние ссылки уходят в системный браузер.
- **Меню** — «Файл» (показать папку с данными, сведения о хранилище),
  «Правка» (роли буфера обмена — они же дают горячие клавиши), «Вид», «Справка».

## Безопасность

`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` — renderer
не имеет доступа ни к Node, ни к файловой системе. Наружу выставлен ровно один
метод `journeyman.db(method, ...args)`, а главный процесс исполняет только
методы из белого списка. То есть даже успешный XSS в редакторе текста не
получает доступа к диску за пределами хранилища.

## Как это проверяется

- `npm test` — парсер выражений (48 проверок, перенесены из веб-версии) и
  хранилище (18 проверок: каскадные удаления, сохранность между запусками,
  битый `db.json`, атомарность записи).
- `npm run test:renderer` — все три экрана в headless-браузере поверх
  **настоящего** `storage.js`: создание пространства, объектов, связи, ввод
  текста, загрузка картинки, перезапуск с проверкой, что всё на месте.
- `npm run test:ui` — то же самое в настоящем окне Electron, включая полный
  перезапуск программы. Требует графической оболочки, поэтому гоняется в CI
  под `xvfb`; там же снимаются скриншоты окна.

## Что осталось сделать

1. **Перенос материалов из браузерной версии.** Нужен экспорт в файл на стороне
   сайта и импорт здесь. Сейчас данные из браузера забрать нечем — это главный
   пробел.
2. **Файлы по протоколу вместо загрузки в память** (`jm-asset://`), чтобы
   открытие объекта с тяжёлой музыкой не тянуло её целиком в память.
3. **Резервные копии по расписанию** — раз данные лежат папкой, копию можно
   делать самой программой.
4. **Автообновление** (`electron-updater`) — сейчас новая версия ставится
   вручную поверх старой.
5. **Подпись установщика** — без сертификата Windows показывает SmartScreen.
6. **Поиск по материалам** — на файлах это дешевле, чем было в браузере: весь
   текст уже лежит в одном `db.json`.
